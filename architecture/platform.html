Платформа

Що таке Платформа​

DNIP — це стандарт (специфікація).
Платформа — це той шар, який розуміє стандарт і реалізує його на практиці.

Платформа читає декларації вузла (Node) і забезпечує їхнє виконання.

Завдання Платформи​

  1. Валідація

    • Перевіряє protocol.json та контракти contracts/*.json на відповідність JSON Schema (draft-07).
    • Гарантує, що опис вузла коректний.

  2. Управління transports

    • Підключає брокери повідомлень (amqp, kafka, nats, mqtt, redis).
    • Забезпечує комунікацію між вузлами мережі.
    • Важливо: transports реалізує Платформа, а не adapters.

  3. Gateway

    • Піднімає HTTP-маршрути (gateway.http.routes).
    • Підписується на події (gateway.events).
    • Викликає відповідні дії (actions) у вузлі.

  4. Cronjobs

    • Запускає періодичні завдання згідно з декларацією у protocol.json.

  5. Processors

    • Працює з чергами завдань.
    • Викликає execute та onError для обробників.

  6. Execution context

    • Формує params як input з контракту та context для викликів у protocol.js.
    • Додає context.headers, context.adapters, службові поля (наприклад, error).

Як Node та Платформа працюють разом​

  • Node описує:

    • protocol.json — що вміє вузол;
    • contracts/*.json — які дані приймає/повертає;
    • config.js — конфігурацію;
    • adapters.js — створює адаптери;
    • protocol.js — бізнес-логіку.

  • Платформа:

    • читає ці файли,
    • перевіряє декларацію,
    • підключає transports,
    • виконує gateway, events, cron та processors,
    • викликає логіку з protocol.js.

Суть​

  • DNIP = опис (стандарт).
  • Платформа = виконання (движок, що реалізує стандарт).

Разом вони забезпечують єдиний і прозорий спосіб будувати розподілені системи.
